# CloudLedger v0.1.14

## Updates

- Fixed rclone crypt remote detection during controlled upgrades. The
  operations toolbox now validates the selected remote directly from its
  configured rclone file, including mixed-case remote names, and reports the
  exact missing or invalid remote without exposing secrets.
- Retains monthly financial analysis with member-level expense drill-down and
  the client-version update gate introduced in the v0.1.13 release line.

## Upgrade Notes

- No database schema or SQLx migration changes are required for this release.
- Before upgrading, configure a real rclone `crypt` remote in the active
  `/etc/cloudledger/rclone.conf`, then use menus `7 → 5` and `7 → 6` to verify
  connectivity and encrypted upload/download round trips.
- Deploy the four matching `v0.1.14` GHCR images together: server, PostgreSQL,
  Caddy, and network-anchor. The release branch and packaged client use the
  production API; `main` remains the testing line.
- The previously published `v0.1.13` GitHub Release is superseded by this
  release. Its immutable tag remains retained for auditability and is not
  reused.

## Validation

- Deployment operations toolbox tests, rclone crypt validation tests, release
  policy tests, Rust formatting, strict workspace Clippy, locked workspace
  tests, and the frontend production build passed before publication.
- Formal CI must additionally verify the release branch source, signed APK,
  GitHub Release, and all four versioned GHCR manifests.
